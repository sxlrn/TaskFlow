# TaskFlow — Система управління завданнями та проєктами

TaskFlow — це сучасний вебдодаток для планування проєктів, управління задачами, ведення підзадач (древовидної структури) та командної взаємодії. Додаток розділений на клієнтську частину (Frontend) та серверну частину (Backend).

## 🚀 Основні можливості

- **Канбан-дошка**: Гнучке візуальне управління статусами задач.
- **Типи задач**:
  - `Стандартна` — проходить стандартний флоу (`До виконання` → `В роботі` → `На перевірці` → `Готово`).
  - `Дослідницька` (Research) — вимагає попереднього вивчення, тому додається новий проміжний статус `Дослідження` перед тим, як перейти `В роботу` (`До виконання` → `Дослідження` → `В роботі` ...).
- **Древовидна структура (Вкладені підзадачі)**: Можливість створювати необмежену вкладеність підзадач для декомпозиції великих цілей.
- **Коментарі**: Можливість спілкування виконавців, менеджерів та адміністраторів безпосередньо в картці задачі (з підтримкою редагування власних коментарів).
- **Рольова модель**: Розподіл прав доступу (`Адміністратор`, `Менеджер`, `Працівник`).

---

## 📁 Структура проєкту

- `/backend` — Express.js API, Prisma ORM, інтеграційні тести (Jest + Supertest).
- `/frontend` — React.js (Vite), Tailwind CSS, React Query, компонентні та юніт-тести (Vitest + JSDOM).

## 🛠️ Встановлення та запуск проєкту

### 1. Попередні вимоги
Переконайтеся, що на вашому комп'ютері встановлено:
- **Node.js** (версії 18+)
- **MySQL Server**

---

### 2. Налаштування та запуск Бекенду (Backend)

1. Відкрийте термінал у папці `backend`:
   ```bash
   cd backend
   ```

2. Встановіть залежності:
   ```bash
   npm install
   ```

3. Створіть файл `.env` у папці `/backend` (або скопіюйте з прикладу нижче) та вкажіть налаштування вашої бази даних MySQL:
   ```env
   DATABASE_URL="mysql://root:ВАШ_ПАРОЛЬ@localhost:3306/taskflow"
   JWT_ACCESS_SECRET="access_super_secret_key_taskflow"
   JWT_REFRESH_SECRET="refresh_super_secret_key_taskflow"
   JWT_ACCESS_EXPIRES="15m"
   JWT_REFRESH_EXPIRES="7d"
   PORT=5000
   CLIENT_URL="http://localhost:5173"
   ```

4. Застосуйте схему бази даних (Prisma) та згенеруйте клієнт:
   **ВАЖЛИВО**: Якщо ваш локальний dev-сервер бекенду вже запущений, зупиніть його перед виконанням цих команд, щоб уникнути блокування файлів (EPERM lock).
   ```bash
   npx prisma db push
   npx prisma generate
   ```

5. Запустіть сервер у режимі розробки:
   ```bash
   npm run dev
   ```
   Сервер запуститься на порту **5000** (`http://localhost:5000`).

---

### 3. Налаштування та запуск Фронтенду (Frontend)

1. Відкрийте новий термінал у папці `frontend`:
   ```bash
   cd frontend
   ```

2. Встановіть залежності:
   ```bash
   npm install
   ```

3. Запустіть клієнт у режимі розробки:
   ```bash
   npm run dev
   ```
   Клієнт запуститься на порту **5173** (`http://localhost:5173`).

## 🧪 Автоматичне тестування (Testing)

Ми реалізували **45 автоматичних тестів**, які покривають ключовий бізнес-функціонал як на клієнті, так і на сервері.

### 1. Тести Бекенду (Jest + Supertest — 27 тестів)
Запускають інтеграційні тести API проти мока бази даних Prisma, що гарантує швидкість та ізольованість тестування:
- **Контролер задач (`task.controller.test.ts` — 9 тестів)**: тестує створення `standard` та `research` задач, CRUD, авторизацію та заборону дій працівникам (`worker`).
- **Контролер коментарів (`comment.controller.test.ts` — 9 тестів)**: перевіряє додавання коментарів до існуючих задач, редагування лише власних коментарів авторами та перевірку прав на видалення.
- **Контролер проєктів (`project.controller.test.ts` — 9 тестів)**: тестує створення проєктів менеджерами, перевірку прав на оновлення та видалення проєктів лише закріпленими менеджерами чи адміністраторами.

Запуск тестів бекенду:
```bash
cd backend
npm test
```

### 2. Тести Фронтенду (Vitest + JSDOM — 18 тестів)
Запускають юніт-тести та тести рендерингу компонентів:
- **Логіка статусів (`Tasks.test.tsx` — 10 тестів)**: тестує роботу скінченного автомата переходу статусів (`getNextStatus` та `getNextLabel`) для обох типів задач (`standard` та `research`).
- **Вхід (`Login.test.tsx` — 4 тести)**: тестує рендеринг форми входу, валідацію порожніх полів, успішний вхід та перенаправлення на головну сторінку, а також показ помилок при неправильних даних.
- **Реєстрація (`Register.test.tsx` — 4 тести)**: перевіряє створення акаунтів, взаємодію з API реєстрації, валідацію полів та перенаправлення на вхід.

Запуск тестів фронтенду:
```bash
cd frontend
npm test
```
